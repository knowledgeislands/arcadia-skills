# Outcome-authority procedure

Use this procedure only when a human affirmatively grants current autonomous delivery authority and names a repository or roadmap outcome. “Crack on with this repository’s roadmap and finish the non-contentious work” qualifies; silence, a standing preference, a clean gate, an ordinary implementation request, or a historic instruction does not.

Resolve the selected local adapter, use `ki-next` to rank eligible records, and use `ki-plan` to make admitted drafts Ready. The human delegates candidate selection, so do not require a second exact-item confirmation or reviewed batch-payload checkpoint.

Exclude work with unresolved public-contract choices, destructive or irreversible actions, external coordination, unavailable verification, or decisions the outcome instruction did not cover. Park an affected item with evidence while continuing only items proven independent.

Create the exact authorisation before the first implementation. Set `authority_mode: outcome`, record concise `authority_evidence`, name the selected duplicate-free items, boundaries, checks, timebox, and mandatory stops, then bind the generated contract with its SHA-256 and run marker. The hash proves the delivered run stayed within the generated contract; it does not claim the human reviewed every selected item.

When the human explicitly requests autonomous completion or consolidated acceptance, set `completion_target: done` and make `closure_item_ids` exactly equal `item_ids`. Each record must still reach `awaiting-review` through `ki-implement`, pass its own review-packet recheck, and close through `ki-accept`. Otherwise use `awaiting-review` and omit closure authority.

The contract is both a boundary and the consolidated review surface. Record excluded candidates and why, every item outcome, verification, remedial follow-ups, and any parked stop. Non-blocking improvement opportunities become receiver-owned roadmap items rather than keeping viable verified delivery open.
